# 모아잡 · MOAJOB — 기업 평점·공고 카드 개선본

검색 화면의 최대 가로 폭을 1,200px로 제한하고, 첨부 HTML의 파랑(#3182f6)·옅은 파랑(#eaf2ff)·회색(#f4f6f8)·흰색 테마를 적용했습니다. 상단 홍보 문구와 장식, 중복 안내 배너, 저장 검색 영역, 직접 추가 버튼, 하단 홍보 문구를 제거했습니다. 검색·상세 필터·관심 공고·지원 현황·연동 설정·백업 기능은 유지합니다. 기존에 저장된 개인 공고와 검색 기록은 백업 호환성을 위해 보존합니다.

기존 자동 검사와 DOM 실행 기반 화면 동작 검사를 통과했습니다. 실제 브라우저의 시각적 배치는 확인하지 못했습니다.


## 이번 수정 내용

- 원티드 공개 검색 연결: 검색어, 20건 단위 더보기, 관심 공고 저장, 원문 정보 재확인 지원
- 최신 등록순·마감 임박순·기업명순 정렬: 등록일 미기재 공고는 최신순에서 뒤쪽에, 상시·미기재·마감 공고는 마감 임박순에서 뒤쪽에 표시
- 공고 카드·상세·지원 현황의 버튼명을 **기업 평점·리뷰**로 통일했습니다. 기업명으로 잡플래닛 기업 검색 결과를 새 창에서 엽니다. 평점 숫자 표시·자동 조회·수동 입력 기능은 제거했습니다.
- 회사명 첫 글자를 크게 표시하던 장식과 정렬 설명 문구를 제거했습니다.
- 공고 카드의 내용·빈 공간을 클릭하면 상세창이 열립니다. 키보드 Enter·Space도 지원합니다.
- 카드에 **공고 바로가기** 버튼을 추가했습니다. 하트·기업 평점·리뷰·공고 바로가기는 각 기능만 동작합니다.
- 상세창 바깥을 클릭하면 닫힙니다. 내부 내용 클릭은 창을 유지합니다.
- 잡코리아 상시채용의 임시 날짜 `2070-01-01`을 남은 날짜로 계산하지 않도록 수정: 신규 검색과 기존 저장 공고에 모두 적용
- 전체 명시적 글자 크기를 약 10% 확대하고, 조건·날짜·설명 텍스트를 진한 회색으로 조정
- 공고 상세창의 원문 공고 보기 버튼을 진한 파란색 배경·흰색 글자로 강조
- 이전 수정의 파랑·회색·흰색 테마, 불필요한 영역 제거, 검색 화면 최대 1,200px 유지

GitHub에 ZIP 안의 전체 파일을 같은 경로로 덮어쓴 다음 검색 서버에도 최신 코드를 배포해야 원티드 검색이 반영됩니다. Render 자동 배포를 사용하는 경우 GitHub 변경 후 새 배포가 Live가 되었는지 확인하세요.

원티드의 공개 검색 응답을 활용하는 연동이며, 공식 OpenAPI 계약·인증키 연동과는 별개입니다. 이번 작업 환경에서는 별도 키 없이 실제 1·2페이지 각 20건과 원문 재확인을 확인했습니다. 원티드 측 접근 제한·응답 구조 변경 시 실패 상태를 표시합니다. 목록에서 제공하지 않는 등록일·학력·고용 형태·급여는 만들어 넣지 않으며 원문 재확인으로 보완합니다.

기존 자동 검사, 원티드 API·페이지 이동·원문 재확인 검사, 날짜 오류·정렬·저장 데이터 검증은 통과했습니다. 실제 브라우저 화면 검증은 진행하지 못했습니다.

설명서 대신 모아잡 화면이 열리도록 최상위 `index.html`을 추가하고, `/moajob/` 아래에서도 화면 파일을 찾도록 경로를 수정했습니다. **실제 공고 검색에는 별도 검색 서버가 필요합니다.** 기존 ChatGPT Site 주소에 의존하지 않습니다.

## 1. 수정본 업로드 → 모아잡 화면 열기

1. ZIP을 풀고 **폴더 안의 파일과 폴더 전체**를 [저장소 업로드 화면](https://github.com/gyeongseop97/moajob/upload/main)에 올립니다. ZIP 자체를 올리지 않습니다.
2. 기존 파일은 같은 이름으로 덮어씁니다. 최상위에 `index.html`, `render.yaml`, `server.mjs`, `package.json`, `public` 폴더가 있어야 합니다.
3. **Settings → Pages → Deploy from a branch → main → /(root) → Save**로 설정합니다. 이미 이렇게 되어 있다면 그대로 둡니다.
4. 배포가 끝나면 [GitHub Pages 모아잡](https://gyeongseop97.github.io/moajob/)을 새로고침합니다. 화면은 열리며, 서버 연결 전에는 실제 검색에 필요한 연결 안내를 표시합니다.

GitHub Pages는 첫 화면으로 index.html, index.md, README.md를 찾습니다. 변경 반영에 최대 10분 정도 걸릴 수 있습니다. [GitHub 공식 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## 2. 실제 검색 서버 만들기 — 한 번만 필요

수정본을 GitHub에 올린 **다음에** 아래 링크를 누릅니다.

**[Render에서 모아잡 검색 서버 만들기](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fgyeongseop97%2Fmoajob)**

Render에 로그인하고 서비스 구성에서 **Free** 항목을 확인한 후 배포합니다. 포함된 `render.yaml`이 Node 버전, 실행 명령, 연결 허용 주소를 설정합니다. `Live` 상태가 되면 발급된 **https://…onrender.com** 주소를 복사합니다. 이 작업은 사용자 Render 계정에서 진행하며, 이 ZIP을 받는 것만으로 서버가 배포되지는 않습니다.

자동 설정 대신 Web Service로 직접 연결할 때:

| 항목 | 값 |
| --- | --- |
| Repository | gyeongseop97/moajob |
| Branch | main |
| Language | Node |
| Build Command | npm ci |
| Start Command | npm start |
| Instance | Free |
| Health Check Path | /health |

환경변수는 NODE_VERSION=24, HOST=0.0.0.0, ALLOWED_ORIGINS=https://gyeongseop97.github.io 입니다. PORT는 Render가 지정합니다. [공식 배포 안내](https://render.com/docs/deploy-node-express-app), [Blueprint 설정](https://render.com/docs/blueprint-spec).

무료 서버는 15분 동안 요청이 없으면 잠들고 첫 연결에 약 1분이 걸릴 수 있습니다. [Render 무료 서비스 안내](https://render.com/docs/free).

## 3. GitHub Pages에서 검색 서버 연결하기

1. [모아잡](https://gyeongseop97.github.io/moajob/)의 **연동 사이트 → 검색 서버 연결**을 엽니다.
2. 발급된 Render 주소를 붙여넣고 **연결 확인**을 누릅니다.
3. 연결 성공 후 **공고 탐색**에서 검색합니다. 검색·더보기·관심 공고 원문 확인이 연결된 서버를 이용합니다.

서버 주소는 이 브라우저에만 저장합니다. 다른 기기에서도 이용하려면 같은 설정을 하거나, GitHub의 `public/config.js`에서 `apiBaseUrl`에 배포 주소를 넣고 저장하면 됩니다. 비밀키는 넣지 마세요. Render 사이트 주소 자체에서도 모아잡을 바로 이용할 수 있습니다.

다른 GitHub 계정으로 옮기면 render.yaml의 ALLOWED_ORIGINS를 새 https://계정.github.io 출처로 변경하세요. 경로 /moajob/는 이 값에 넣지 않습니다. 관심 공고와 메모는 서버로 전송되지 않으며 기존 JSON 백업으로 옮길 수 있습니다.

## 내 컴퓨터에서 실행하기

Node.js 22.13 이상, 25 미만에서 프로젝트 폴더의 터미널에 입력합니다.

~~~sh
npm install
npm start
~~~

http://localhost:3000/explore 로 접속합니다. 로컬 서버나 Render 전체 사이트에서는 별도 검색 서버 연결이 필요하지 않습니다.

## 포함된 기능

- 사람인·잡코리아·인크루트·원티드 통합 검색, 사이트별 연결 상태 표시
- 더보기, 같은 원본 공고 중복 제거, 조건 일치 공고 추가 탐색
- 전국 지역·근무지·경력·고용 형태·학력·연봉·마감·등록일·포함/제외 키워드 필터
- 조건 일치와 정보 확인 필요 공고를 별도 목록으로 표시
- 기업·제목·근무지가 일치하는 사이트 간 중복 추정 공고 묶기와 원본 링크 유지
- 메뉴 이동·새로고침·뒤로가기 시 검색 조건과 결과 복원, 검색 주소 공유
- 관심 공고, 지원 상태, 메모, JSON 백업 내보내기·가져오기
- 관심 공고 원문·마감 재확인

독립 실행 검증 과정에서 원문 공고의 1~100년 경력 범위를 처리하도록 보완했습니다. 형식이 잘못된 공고 한 건 때문에 전체 결과가 사라지지 않도록 개별 검증도 적용했습니다. 직접 입력하는 경력의 0~50년 제한은 유지합니다.

리멤버는 현재 미연결입니다. 화면에 연결된 것처럼 표시하거나 공고를 생성하지 않습니다.

## 데이터와 검색 범위

관심 공고·메모는 브라우저의 `localStorage`에, 최근 가져온 결과는 `sessionStorage`에 저장합니다. 다른 기기나 주소로 옮길 때는 화면의 **연동 사이트 → 내 데이터 내보내기 / 백업 가져오기**를 이용하세요. 기존 모아잡에서 내보낸 백업도 가져올 수 있습니다.

검색 필터는 **지금까지 가져온 공고**에 적용됩니다. 더보기로 페이지를 확장할 수 있으며 사이트별 한 번의 검색에서 최대 100페이지까지 지원합니다. 공유 주소의 결과를 새 환경에서 복원할 때는 우선 최대 5페이지를 가져오고, 이후는 더보기로 이어 갑니다.

서버의 검색 캐시는 최대 5분, 원문 정보 캐시는 최대 10분 동안 재사용됩니다.   사이트를 닫아 둔 동안 자동으로 확인하거나 알림을 보내는 기능은 없습니다.

공개 검색 화면의 구조 변경이나 접근 제한이 생기면 연결 실패 상태를 표시합니다. 실패한 사이트를 ‘공고 0건’으로 간주하지 않습니다. 최종 지원 조건과 채용 여부는 원본 링크에서 확인할 수 있습니다.

## 실행 명령

| 명령 | 내용 |
| --- | --- |
| `npm start` | 서버 실행 |
| `npm run dev` | 서버 코드 변경 시 재시작하는 개발 모드 |
| `npm test` | 외부 채용사이트에 접속하지 않는 자동 검사 |
| `npm run test:live` | 네 사이트에 실제 검색 요청을 보내 연결 상태 확인 |

PowerShell에서 `npm` 실행 정책 오류가 발생하면 같은 명령의 `npm`을 `npm.cmd`로 바꿀 수 있습니다.

## 포트와 배포

기본 포트는 `3000`이며 `PORT`, `HOST` 환경변수로 바꿀 수 있습니다.

```powershell
# Windows PowerShell 예시
$env:PORT = "8080"
$env:HOST = "127.0.0.1"
npm start
```

`.env.example`을 `.env`로 복사해 사용하는 경우에는 다음 명령을 사용합니다. `npm start`는 `.env`를 자동으로 읽지 않습니다.

```sh
node --env-file=.env server.mjs
```

서버에 배포할 때는 Node.js 22.13 이상, 25 미만을 사용하고, 설치 명령은 `npm ci`, 시작 명령은 `npm start`로 설정합니다. 별도 빌드 단계는 없습니다. 호스팅에서 제공하는 `PORT`를 사용하고 외부 접속용 `HOST`는 `0.0.0.0`으로 설정합니다. 상태 확인 주소는 `/health`입니다.

GitHub Pages에서는 화면만 실행합니다. 실제 검색은 연결한 Node.js 서버에서 처리합니다. Render의 전체 사이트 주소로 접속하면 별도 연결 설정 없이 사용할 수 있습니다.

## 코드 구조

```text
index.html                   GitHub Pages 첫 화면
render.yaml                  Render 무료 검색 서버 배포 설정
server.mjs                   HTTP 서버와 API 경로
public/
  explore.html               화면 구조
  style.css                  화면 스타일과 모바일 배치
  config.js                  기본 검색 서버 주소 (선택)
  backend.js                 서버 연결 확인과 주소 저장
  app.js                     검색·저장·복원·메모·새 공고 비교
  core.js                    데이터 검증과 기본 기능
  domain.js                  필터·중복·마감 판정
lib/
  job-search.mjs             사이트별 검색과 페이지 확장
  listing-metadata.mjs       공개 목록의 정보 보완
  job-details.mjs            공개 원문과 마감 재확인
  detail-cache.mjs           원문 정보 캐시
tests/                       API와 파서 검사
scripts/check-live.mjs       실제 연결 확인
.github/workflows/test.yml   GitHub 자동 검사
```

채용 API는 `GET /api/search?q=기획&sources=saramin,jobkorea,incruit`와 `POST /api/jobs/refresh`를 제공합니다. 페이지를 지정할 때는 `pages`에 `{"saramin":2,"jobkorea":2,"incruit":2}`를 JSON으로 넣습니다. 원문 확인 요청 본문은 `{"ids":["live-jobkorea-12345"],"fresh":true}` 형태이며 한 번에 최대 5건을 확인합니다.

이 코드 묶음에는 기존 호스팅의 프로젝트 ID, 인증정보, Git 이력, 임시 수집 결과, 개인 백업 파일이 포함되지 않습니다.

## 이 수정본의 검증 범위

GitHub Pages와 같은 /moajob/ 경로에서 첫 화면과 파일 로딩, 서버 연결, 실제 검색, 더보기, 원문 확인 요청, 새로고침 복원과 모바일 화면을 확인했습니다. API 검사에는 허용된 출처의 검색·JSON 원문 확인과 허용하지 않은 출처의 차단이 포함됩니다. Render의 실제 계정 배포와 GitHub 저장소 수정은 이 파일 제공에 포함되지 않으며 위 절차로 사용자가 진행해야 합니다.
